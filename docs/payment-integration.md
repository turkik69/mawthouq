# عقد ربط بوابة الدفع

## ما يعمل الآن

- ينشئ الخبير المعتمد عرض سعر `payments.status = pending` مرتبطًا بمحادثة وطرفين ومبلغ بالريال العُماني.
- يوافق الطالب صاحب المحادثة عبر `accept_payment_quote` فتنتقل الحالة إلى `approved` ويُسجل وقت الموافقة. **لا تُحصّل أموال في هذه الحالة.**
- تبقى وظائف الاختبار القديمة التي تغيّر الحالة إلى `held` أو تسجل صرفًا ماليًا محجوبة من أدوار المتصفح.
- توجد أعمدة مرجع المزود وسجل أحداث خاص `app_private.payment_gateway_events` بمفتاح تفرد `(gateway_name, gateway_event_id)` لدعم منع معالجة الحدث مرتين.

## العقد المطلوب عند اعتماد مزود رسمي

1. اختر مزودًا يسمح لنشاط المنصة وآلية تسوية مستحقات مقدمي الخدمة. ثبّت اسم الجهة القانونية والحساب البنكي ورسومها وشروط الاسترداد والعقد التجاري.
2. أنشئ وظيفة خادمية تنشئ جلسة دفع فقط لعرض `approved` لم تنته صلاحيته. احسب المبلغ بوحدة **بيسة صحيحة** (`1 ر.ع = 1000 بيسة`) من قيمة قاعدة البيانات، ولا تثق بالمبلغ أو معرف الطالب المرسل من المتصفح. استخدم مفتاحًا ثابتًا لمنع تكرار إنشاء الجلسة.
3. أعد للمتصفح رابط التحويل إلى صفحة المزود الرسمية فقط. لا تمرر مفاتيح سرية أو أرقام البطاقات عبر الواجهة أو قاعدة البيانات.
4. تحقق من توقيع أو سر إشعار المزود، وأصل الطلب، ومرجع العملية، وحالة المزود، وتطابق المبلغ والعملة والطلب. سجّل رقم الحدث وبصمة المحتوى في `app_private.payment_gateway_events`، ثم غيّر `approved -> held` داخل معاملة واحدة بعد نجاح التحصيل **المؤكد**. تجاهل التكرارات؛ لا تعتمد صفحة العودة لإثبات الدفع.
5. عالج فشل الدفع وانتهاء الجلسة وإعادة المحاولة دون تكرار المبلغ. لا تسمح بإتمام التسليم المالي عبر زر في لوحة المشرف. أكمل الاسترداد والنزاعات والتسوية وفق واجهة المزود والعقد؛ وسجّل معرف العملية والوقت وفاعل كل تغيير.
6. اعرض إيصالًا رسميًا، ورسوم المنصة، وصافي مستحق الخبير، وحالة التسوية الفعلية. غيّر النصوص الحالية المتعلقة بالمرحلة التجريبية **بعد اجتياز اختبارات sandbox واعتماد الحساب البنكي**.

## اختبارات قبول الربط

نجاح الدفع، فشله، إلغاء العميل، رجوع المتصفح قبل webhook، وصول webhook مرتين، اختلاف المبلغ أو العملة، انتهاء جلسة الدفع، طلبان متوازيان، استرداد جزئي وكامل، نزاع، وتعطل خدمة المزود. اختبر أن دور `anon` والطالب والخبير لا يستطيعون تغيير `status` أو `gateway_reference` مباشرة.

**القرار المتعمد:** لم أضع اسم مزود أو مفاتيح أو روابط دفع شكلية؛ تُستكمل نقطة الربط بعد اعتمادك المزود والحساب البنكي.
