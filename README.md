# موثوق

منصة عربية للاستشارة والمراجعة البحثية. الواجهة ثابتة (HTML/CSS/JS)، والهوية والطلبات والمحادثات والملفات على Supabase. الدفع الإلكتروني **غير مفعل** حتى اكتمال اعتماد الجهة والحساب البنكي وربط مزود دفع رسمي.

## التشغيل

انشر جذر المستودع على نطاق HTTPS. نقطة الدخول `index.html`. اضبط نطاق الموقع وروابط إعادة التوجيه داخل Supabase Auth. يعتمد `assets/supabase-config.js` على مفتاح **publishable** عام؛ لا تضع فيه مفتاح `service_role` أو مفاتيح الدفع. يحتفظ خادم Supabase بمفاتيح إشعارات الويب ضمن أسراره.

للتطوير المحلي يمكن تشغيل خادم ملفات ثابتة مثل `python3 -m http.server 8000`، ثم فتح `http://localhost:8000`. يتطلب اختبار تسجيل الدخول أن يُسمح بعنوان التطوير في إعدادات Auth. لا تستخدم بيانات مستخدمين حقيقية في التطوير.

## قاعدة البيانات

ملف `supabase/schema.sql` سجل للبنية الأولى **وليس أمرًا لإعادة تشغيله على المشروع الحي**. سُجلت تعديلات الجاهزية في مشروع Supabase بالترتيب التالي، وتوجد نسخها في المستودع:

1. `supabase/production_readiness.sql`
2. `supabase/production_readiness_files.sql`
3. `supabase/payment_gateway_preparation.sql`
4. `supabase/suspended_provider_guard.sql`
5. `supabase/provider_identity_verification.sql` — تخزين خاص للبطاقة المدنية ومراجعة منفصلة لشارة الثقة.
6. `supabase/provider_identity_revocation.sql` — سحب شارة الثقة عند الحاجة.

أي تغيير لاحق في قاعدة البيانات يحتاج ترحيلًا مستقلًا ومراجعة سياسات RLS واختبار مستخدم زائر وطالب وخبير ومشرف. لا تنسخ القاعدة الحية إلى مستودع عام. راجع [خطة التشغيل](docs/operations.md) و[خطة الدفع](docs/payment-integration.md).

## التحقق

شغّل `node scripts/check.mjs`. افحص مستشار أمان Supabase بعد أي ترحيل، واختبر مسارات التسجيل والنشر والملفات والرسائل والموافقة على عرض السعر قبل الإطلاق.

الصفحات القانونية الحالية تصف المرحلة السابقة للدفع، ويجب استكمال بيانات الجهة المشغلة ومراجعتها قبل إطلاق خدمة مالية للجمهور.
